Important business rules

Order ID / case ID:
- order_id is the case/accession ID
- format is SU + 2-digit year + 7-digit sequence
- example: SU250000001
- sequence resets every year
- backend generates it, never frontend
- generation must be concurrency-safe
- explicitly warn against naive max+1 without locking

Specimen IDs:
- generated by backend only
- format: {order_id}-A, -B, ... -Z, -AA, -AB, etc.
- need Excel-like alphabetic suffix generation

Block IDs:
- generated by backend only
- format: {order_id}-{specimen_code}{block_number}
- example: SU250000001-A1

Slide IDs:
- generated by backend only
- format: {order_id}-{specimen_code}{block_number}-S{slide_number}
- example: SU250000001-A1-S1
- no separate slide level field because the naming already covers it

Report behavior:
- multiple reports per order
- versioned
- signed-out reports are immutable
- version_number increments per order
- signed_out_datetime needs to be present
- pathologist_employee_id is the sign-out user
- is_amendment supported
- supersedes_report_id links report lineage
- orders.status is one of PENDING | HOLD | COMPLETED | CANCELLED | REACTIVATED
- orders.is_reactivated indicates reopened case
- orders.reactivated_from_report_id points to prior report that triggered reactivation
- reactivation should create a new draft version, not overwrite an old final report

How file/PDF storage should be described

Important nuance:
- the schema can remain conceptually future-facing
- but in practice the app should store generated PDFs in the filesystem for local/dev use
- report_file should be treated as metadata/path-oriented in the implementation

Frontend requirements

Login:
- simple passwordless login
- user can search existing employees by name or username
- or enter a new employee
- entering a new employee inserts into DB
- minimum fields:
  - first_name
  - last_name
  - user_name
  - employee_role
- only roles needed now:
  - Pathologist
  - Technologist

Order Entry page:
- form-based case creation
- structured required fields at minimum:
  - patient identifier
  - patient first name
  - patient last name
  - DOB
  - sex
  - clinician
  - case date / registered date
  - specimen type
  - body site
  - clinical_history
- should allow choosing existing patient/doctor or creating new ones
- should allow entering multiple specimens inline during case creation
- after creation, show generated case ID prominently
- provide button to download worksheet PDF

Worksheet PDF requirements:
- generated on backend
- use backend PDF library, ideally pdf-lib
- include case ID in large bold font
- include patient details
- include specimen types and sites
- include clinician and date
- include blank/empty areas for clinical notes and gross description

Processing page:
- paginated queue
- default view: registered cases with no materials
- toggle: show all registered not signed out
- “materials” means blocks or slides exist
- clicking row opens case-specific processing page
- processing page allows:
  - view case/specimens
  - create blocks for specimens
  - create slides for blocks
  - immediately show generated IDs
  - view existing materials
- also provide downloadable reference strips PDF
- the H&E worklist (and other ancillary worklists) supports a recency filter
  (1d / 7d / 30d / All) when viewing terminal statuses (DISTRIBUTED, CANCELLED)
  so historical entries don’t accumulate forever in the default view
- “Add 1 slide to all” on the ancillary worklist deduplicates by blockId, so a
  panel of N tests on the same block produces a single new slide, not N

Reference strips PDF:
- downloadable
- regular paper, not special label printer assumptions
- IDs should be large and readable
- group sensibly by case/specimen/material

Result page:
- paginated queue
- queue definition: materials available but not signed out
- “materials available” = at least one block with heStatus=DISTRIBUTED, OR
  at least one ancillary order on the case in DISTRIBUTED
- row click opens case-specific result page
- page should show order/patient/clinician/specimens/materials/prior reports
- result form fields:
  - diagnosis
  - comment
  - template
  - gross
  - pathologist
- “Edit Order” button on the result page lets a user set order.status to
  PENDING / HOLD / CANCELLED while the case is open
- “Preview PDF” button on the draft toolbar renders a draft report PDF from
  the current (unsaved) form content; result is watermarked DRAFT PREVIEW and
  is not persisted

Sign-out behavior:
- validate required result content
- workflow guard: every non-discarded block on the case must have
  block.heStatus === 'DISTRIBUTED' before final sign-out is allowed
- persist/finalize report version
- set signed_out_datetime
- set pathologist_employee_id from logged-in employee
- generate report PDF
- save report_file metadata/path
- case should drop out of pending result queue when appropriate

Reactivate / revise / addend:
- prior signed-out report stays unchanged
- order marked reactivated
- new draft report version created
- amendment/addendum workflow supported
- version history visible in UI
- on the H&E worklist, reactivating a DISTRIBUTED block returns block.heStatus
  literally to MICROTOMY (no auto-promote based on existing slides)

Query page:
- search by order ID or patient ID
- results as table
- clicking a result should take user to the corresponding result page for that case

- internal app feel, desktop-first
- use a shell layout with navigation
- paginated tables / DataGrid

What the DBML needs to contain

doctor
- doctor_id bigint [pk, increment]
- last_name varchar(100) [not null]

patient
- patient_id varchar(50) [pk]
- last_name varchar(100) [not null]
- first_name varchar(100) [not null]

employee_role
- employee_role_id int [pk, increment]
- role_name varchar(30) [not null, unique]
- note mentioning Pathologist / Technologist examples

employee
- employee_id bigint [pk, increment]
- last_name varchar(100) [not null]
- first_name varchar(100) [not null]
- user_name varchar(100) [not null, unique]

body_site
- body_site_id int [pk, increment]
- body_site_name varchar(255) [not null, unique]

specimen_type
- specimen_type_id int [pk, increment]
- specimen_type_name varchar(255) [not null, unique]
- description text

report_template
- report_template_id int [pk, increment]
- template_name varchar(255) [not null, unique]
- template_text text
- is_active boolean [not null, default: true]

orders
- order_id char(11) [pk]
- patient_id varchar(50) [not null]
- doctor_id bigint [not null]
- case_type varchar(50)
- clinical_history text
- registered_date datetime [not null]
- completed_date datetime
- is_reactivated boolean [not null, default: false]
- reactivated_from_report_id bigint
- include note saying order ID format is SU + 2-digit year + 7-digit yearly sequence

- is_final boolean [not null, default: false]

- supersedes_report_id bigint
- unique index on (order_id, version_number)

report_file
