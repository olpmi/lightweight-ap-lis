## 9. Additions to §6, Limitations

The existing paragraph correctly separates software verification from clinical
validation. Add the following disclosures:

> Verification was performed against a synthetic corpus rather than clinical
> material. The corpus is stratified to populate every workflow stage, but it is
> not clinically representative: body sites are drawn from the full anatomic lookup
> independently of case type, so some cytology cases carry anatomically implausible
> sites; all ancillary orders in the corpus are routine haematoxylin and eosin
> orders, so immunohistochemistry, special-stain, molecular and send-out ordering
> are exercised by automated tests rather than by seeded data; and the corpus
> contains no preliminary reports and no addenda.
>
> Several implemented behaviours remain outside automated coverage: manual
> case-status transitions, block-level haematoxylin and eosin status transitions,
> and the workflow guards that reject premature sign-out.
>
> Performance was characterised on a single host at modest concurrency. The
> benchmark is not a load test and says nothing about sustained multi-user
> throughput or long-run stability.

## 10. Defects found during verification and since fixed

Building the verification artifacts exposed four defects. All are fixed in the
analysed release, and the figures throughout this document are from the fixed
build. They are listed here because they are the substantive result of the
verification exercise: each was invisible to the test suite as it stood, and two
would have made claims in the current manuscript text untrue.

**Report PDFs were never generated.** The production renderer launched headless
Chromium with `--single-process` and `--no-zygote`; modern Chromium exits
immediately under that combination. Because sign-out deliberately catches PDF
errors so they cannot block a clinical action, the failure was silent — cases
signed out, reported success, and produced no PDF and no stored file record. In
the deployment container image, zero report PDFs had ever been produced. Removing
the two flags fixes it; the same 15-case lifecycle run now produces 15 stored
PDFs at 425 ms (p50) per render.

**Patient identifiers repeated every 2.8 hours.** Identifiers were derived from
`Date.now()` truncated to seven digits, which wraps every 10,000,000 ms, and
patient lookup returned any record matching a supplied identifier without
comparing name, date of birth, or sex. A newly registered patient could therefore
be silently merged into an unrelated earlier record and their case filed under the
wrong person. Allocation now comes from a database sequence via a single atomic
increment, and a supplied identifier whose demographics disagree with the stored
record is rejected. This also removes the concurrent-registration failures the
benchmark had measured: 25 simultaneous registrations previously produced six
HTTP 409 responses and now produce none.

**Amended cases never returned to the work queue.** The result-queue predicate
excluded any case with a signed-out report; after an amendment the superseded
version still satisfied it, so a case awaiting a revised sign-out disappeared from
the pathologist's worklist and was reachable only by search. The predicate now
also admits a reactivated case whose amendment is unsigned, and drops it again on
re-sign-out. Ten of the 300 corpus cases are affected, which is why the result
queue in §4 holds 70 cases rather than 60.

**The edit lock was advisory only.** A helper intended to enforce lock ownership
on mutating endpoints was implemented but never called, so a client that bypassed
the user-interface lock could write to a case another user was editing. It is now
invoked inside the transactions of draft creation, sign-out, preliminary sign-out,
and amendment. Clients that hold no lock are unaffected, so the change is
backward-compatible; only an actively contested case is rejected.

Consequently §3.8's description of server-side concurrency control is now accurate
as written, and the manuscript may describe report generation, patient
registration, and amendment workflows without qualification — provided the
analysed commit is the fixed one.
